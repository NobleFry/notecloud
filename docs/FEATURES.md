# NoteCloud 功能列表（v0.2）

> 目标：Vue + Node + MySQL 的可自部署、前后端分离的**小团队协作**知识工作台
> 核心能力：云同步笔记 + TodoList + 分类体系 + 看板 + 账户与工作区权限
> 状态：范围基线。优先级 `P0` MVP / `P1` v1.0 / `P2` v1.5 / `P3` 远期

---

## 0. 定位

一个你自己能装、数据在自己手里的「笔记 + 待办 + 看板」一体化协作平台。**工作区（Workspace）是顶层容器**，成员在其中共享笔记本、标签、看板与任务；服务端是唯一权威数据源，多端（桌面/手机/PWA）同步。

### 已确认的技术决策 ✅
| 决策 | 结论 |
|---|---|
| 使用场景 | **小团队协作**（工作区 + 成员 + 角色权限） |
| 看板模型 | **方案 A：卡片即任务**，看板列 = 任务状态 |
| 笔记编辑器 | **Markdown 分栏预览** |
| 全文检索 | **MySQL 8 `ngram` 全文索引**（零外部依赖） |
| 后端 | **Fastify + Prisma + TypeScript** |

### 非目标（明确不做，防范围蔓延）
- 不做类似 Google Docs 的**字符级实时协同编辑**（OT/CRDT）。协作靠"乐观锁 + 冲突提示 + 实时刷新"实现
- 不做 SaaS 计费/多租户隔离的对外售卖版本（自部署单实例）
- 不做原生 App（PWA 覆盖移动端）

## 1. 账户、工作区与权限系统

> 这一块从"账户系统"升级为"**账户 + 工作区 + 成员 + 权限**"，是全项目的地基，必须最先做对。

### 1.1 认证
| 功能 | 优先级 | 备注 |
|---|---|---|
| 邮箱 + 密码注册 | P0 | argon2 哈希、密码强度校验 |
| 邀请制注册（默认关闭公开注册） | P0 | 团队场景下公开注册是风险，**默认走邀请** |
| 登录 / 登出 | P0 | JWT Access（15min）+ Refresh（httpOnly cookie，7~30 天） |
| Refresh 轮转 + 复用检测 | P0 | 检测到重放则吊销整个会话族 |
| 邮箱验证 | P1 | SMTP 未配置时可跳过，配置项开关 |
| 忘记密码 / 重置 | P1 | 一次性 token，带过期时间 |
| 双因素认证 TOTP | P3 | 团队账号安全增强 |
| Passkey / WebAuthn | P3 | 远期 |

### 1.2 用户资料与安全
- 昵称、头像、时区、语言 `P0`
- 修改密码 / 修改邮箱（需重新验证）`P1`
- 会话与设备管理：查看登录设备、单独撤销、一键登出全部 `P1`
- 登录日志（IP / UA / 时间 / 成败）`P2`
- 账户注销（先导出数据，延迟物理删除）`P2`

### 1.3 工作区（Workspace）
- ✅ 创建/重命名/删除工作区，设置图标与颜色
- ✅ 一人可属于多个工作区，顶部切换器切换
- ✅ 每个用户有默认「个人工作区」，不可被他人加入

### 1.4 成员与角色
角色定义（4 级，够小团队用且不易理解错）：

| 角色 | 说明 |
|---|---|
| `owner` | 创建者，唯一，可转让、可删工作区、可管所有人 |
| `admin` | 管理成员、管理所有资源、管不了 owner |
| `member` | 创建/编辑/删除自己创建的资源，可读工作区公开资源 |
| `guest` | 仅能访问被显式分享给他的资源（外部协作者）`P2` |

功能：
- 成员列表、搜索、移除成员、修改角色 `P0`
- 邀请成员：邮箱邀请 + 邀请链接（可设有效期、可限次、可预设角色）`P0`
- 成员主动退出工作区 `P1`
- 转让所有权 `P1`
- 最后一名 owner 保护（不能退出/降级）`P1`
- 成员活动概览（谁改了啥）`P2`

### 1.5 资源级权限与共享
每个资源（笔记本 / 笔记 / 看板 / 项目）有可见性：
- `private` 仅自己 `P0`
- `workspace` 工作区成员可读（或可编辑，按资源设置）`P0`
- `shared` 通过分享链接给外部人 `P1`
- 单独授权：把某个笔记本/看板分享给指定成员并给 `view` / `edit` `P1`
- 分享链接：公开只读 / 带密码 / 有效期 / 可撤销 `P1`
- 权限继承：笔记本的权限默认向下继承到其中的笔记，可单篇覆盖 `P1`

### 1.6 管理员后台
- ✅ 概览：用户 / 工作区 / 笔记 / 任务 / 附件占用 / 在线会话
- ✅ 用户列表：搜索、启用/禁用（同时吊销会话）、设为/取消站点管理员
- ✅ 强制重置密码：生成临时密码（只显示一次）
- ✅ 不变量：不能操作自己、不能降级/停用最后一个可用管理员
- ✅ 首次启动向导：首个注册用户成为站点管理员
- ❌ 站点设置可视化（站点名/注册开关等仍读 `.env`）
- ❌ 全部工作区列表与用量
- ❌ 审计日志界面（`audit_logs` 只写不读）

## 5. 看板模块

### 5.1 数据模型 ✅ 卡片即任务（已实现）
`board` → `board_column`（映射任务的一个阶段/状态） → **卡片就是 `tasks` 记录**。
- 拖进某列 = 改 `tasks.columnId` + 把 `status` 同步成该列的 `status`
- 因此在待办里改了状态、在看板上也能看到；反之亦然，不存在两边数据不一致
- 排序用 `tasks.position`（列内），拖拽时按客户端提交的完整顺序整组重写

### 5.2 能力
- ✅ 看板 / 列 / 卡片 CRUD；新建看板自动带「待办 / 进行中 / 已完成」三列
- ✅ **把已有待办加进看板**：列底部「从待办添加」，或在任务详情里选「看板列」
- ✅ 拖拽：列内排序、跨列移动（移动即改状态）
- ✅ 列：重命名、改映射状态、改颜色、设置 WIP 上限、删除
- ✅ 列数上限 20，工作区看板上限 50
- ✅ WIP 上限：超限拒绝并提示（列内重排不受限）
- ❌ 泳道（按负责人/标签/优先级分组）
- ❌ 多视图切换：列表 / 表格
- ❌ 过滤器（复用智能视图）
- ❌ 看板级权限（可见范围 + 可编辑者）—— 目前工作区成员都能编辑，GUEST 授权在 M5

## 6. 云同步与并发

### 6.1 同步模型
- ✅ 服务端为唯一权威源
- ✅ 每条记录带 `updatedAt` + `version`（乐观锁）
- ✅ **变更日志**：`sync_changes`（`seq` 自增游标）+ `GET /sync/changes?since=`
- ✅ 删除以 `op=delete` 记录（逻辑墓碑，不另建墓碑表）
- ✅ **冲突策略**：保存带 `version`，不一致 → `409` + 服务端最新内容，前端让用户选
  （绝不静默后写覆盖）

### 6.2 离线与实时
- ✅ WebSocket 广播：`notification` / `note.changed` / `task.changed` / `board.changed`
- ✅ 断线指数退避重连（封顶 30 秒）；认证失败（4401）不重连
- ✅ PWA：manifest + Service Worker，离线可打开应用外壳
- ❌ **离线数据同步**（IndexedDB 缓存 + 操作队列重放）—— 目前只缓存外壳
- ❌ 在线状态 / "正在编辑"提示
- ❌ 手动同步按钮与同步状态指示
- ❌ 多实例部署的实时广播（连接表在进程内存，需 Redis pub/sub）

## 11. 技术方案（已冻结）

### 已定 ✅
- 前端：Vue 3 + Vite + TypeScript + Pinia + Vue Router
- 后端：Fastify + TypeScript + Prisma + Zod
- 数据库：MySQL 8.0+（`utf8mb4` / `utf8mb4_0900_ai_ci`），全文检索用 `ngram` 解析器

- 看板：卡片即任务；编辑器：Markdown 分栏

### 已定 ✅（补充）

- UI 组件库：**Naive UI**（不用 Element Plus，也不上 Tailwind）
- 编辑器：**CodeMirror 6 自封装**（不用 md-editor-v3）
- 实时层：**原生 `ws`**
- 附件存储：**本地磁盘**，存储层做抽象，后续可切 MinIO
- 注册：**邀请制**（关闭公开注册），SMTP 暂缓
- 拖拽：暂用原生 HTML5 drag，未引入拖拽库
- 依赖版本策略：**全用最新稳定版**（Prisma 7 / Zod 4 / Vite 8 / Pinia 4 / vue-router 5）


关键索引：`notes(workspaceId, deletedAt, updatedAt)`、`notes(workspaceId, isStarred)`、

### API 约定
- RESTful，前缀 `/api/v1`；统一响应 `{ code, message, data, requestId }`
- 分页：游标优先（`cursor + limit`）
- 鉴权：`Authorization: Bearer <access>`；Refresh 走 httpOnly cookie
- 所有工作区资源路由都带 `/:workspaceId` 前缀，中间件统一校验成员身份

## 14. 风险与注意点

- **权限校验必须集中在中间件/服务层**，不能散落在各 controller，否则越权是迟早的事
- **笔记可见性过滤**（`PRIVATE` vs `WORKSPACE`）必须在**每一处**读取笔记的查询里出现，漏一处就是越权泄漏；
  已收敛到 `visibilityFilter()` 单点维护
- **软删除 + 唯一索引冲突**：`UNIQUE(workspaceId, name)` 在软删场景下拦不住同名，需要把 `deletedAt` 放进唯一键或走应用层校验
- **NGram 全文索引**：Prisma 不原生支持 `WITH PARSER ngram`，只能手写原生 SQL 维护迁移。
  ⚠️ 更要命的是 **Prisma 会把这类索引当成 drift，每次 `migrate dev` 都生成 `DROP INDEX`** ——
  M3 的迁移就因此把笔记的全文索引删了，中文搜索直接失效。必须走 `pnpm db:deploy` / `pnpm db:migrate`（内置索引自愈脚本），
  不要直接调 `prisma migrate`
- **回收站到期清理还没做**：目前只有 `deletedAt` 和前端天数提示，数据会一直留在库里
- **乐观锁与实时广播的竞态**：M5 接入 WebSocket 后，多端同时编辑的 `version` 冲突会更频繁，前端提示必须清晰
- **升级路径向后兼容**：自部署产品不可能强制用户停机迁移，Prisma migrate 必须可前向兼容
- **编辑器 chunk 体积**：CodeMirror + markdown-it + highlight.js 约 530KB（gzip 198KB），已做路由级 + 组件级懒加载
